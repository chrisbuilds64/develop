## Part 1 — Dependencies between cases

- `casefile/domain/depends.py`: references `CASE` or `<instance>:CASE`, kept in `meta.json` under `waitsFor`;
  resolution, release, the checks for existence, reach, self and circles.
- Step `wait_for` (`domain/step.py`): replaces the list, journaled, a thread entry; an empty list ends the waiting.
- The case view carries `waits` and `released` (`api/views.py`); API contract and types regenerated.
- Tests: `tests/test_depends.py`.

**Deviations from REQ-005**

- *Other instances* are reached through `targets.json` (ADR-022/023) until ADR-032's bindings exist. The resolver is
  one function (`depends.resolver_for`), so the switch touches nothing else.
- *Closed* means the case stands in a stage of group `out` or `archive` — the same groups the core already closes a
  case into. No new stage flag.
- *Released* is computed when the case is read, not stored and not announced in the thread.
- A circle running through a third instance is caught when that instance sets its own reference, not from here: a case
  reaches only the instances its own resolver reaches.
- The surface does not show `waits` yet; it arrives with the worklist's configuration (part 2).

## Part 2 — Configuration and demo world

- `config/worklist/`: stages Backlog, Next, Doing, Waiting, Done; every open stage offers a move to every other; whose
  move it is comes from the item's assignee; every member is an operator. Value lists: area (the cluster prefixes),
  priority, origin. Words in German and English.
- Core, for every application (Rule 17 — configuration, not a special case):
  - `field:<key>` as an actor (`domain/turn.py actor_of`): whose move is whoever the case's meta names there.
  - Declared fields (`domain/fields.py`, `theme.fields`): person, date, text or a value list; the step `set_fields`
    changes them, journaled, the thread names old → new; a new case may carry them.
  - `theme.create.slug: false`: the number alone is the case's name (`SYS-148`, not `SYS-148-title`).
- Demo world `build_worklist` (fictional), first in the public demo's list of worlds.
- Tests: `tests/test_worklist.py`.

**Deviations from REQ-005**

- *Creator* is the core's `created_by`; no second field.
- *Done sets the closing date* is the date of the move into Done, read from the thread; no `closed` field is written.
- An agent member cannot *reopen* a done item: the core reserves reopening to people (review S4). Agents move every
  open item.
- *Assignee* is checked against the instance's `people.json`, not a value list, so there is one list of people.
- Numbering counts within one data tree. Unique numbers across several data points of one instance follow in part 3.

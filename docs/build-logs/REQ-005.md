## Part 1 — Dependencies between cases

- `casefile/domain/depends.py`: references `CASE` or `<instance>:CASE`, kept in `meta.json` under `waitsFor`;
  resolution, release, the checks for existence, reach, self and circles.
- Step `wait_for` (`domain/step.py`): replaces the list, journaled, a thread entry; an empty list ends the waiting.
- The case view carries `waits` and `released` (`api/views.py`); API contract and types regenerated.
- Tests: `tests/test_depends.py`.

**Deviations from REQ-005**

- *Other instances* are reached through `targets.json` (ADR-022/023) until ADR-032's bindings exist. The resolver is
  one function (`depends.resolver_for`), so the switch touches nothing else.
- *Closed* means the case stands in a stage of group `out` or `archive` — the same groups the core already closes a
  case into. No new stage flag.
- *Released* is computed when the case is read, not stored and not announced in the thread.
- A circle running through a third instance is caught when that instance sets its own reference, not from here: a case
  reaches only the instances its own resolver reaches.
- The surface does not show `waits` yet; it arrives with the worklist's configuration (part 2).
